================================================================================
ROOT CAUSE ANALYSIS
================================================================================

1. AUTHORIZATION MIDDLEWARE ISSUE
   - Admin routes used authorizeRoles("admin", "manager")
   - Did NOT include "ceo" role in the allowed roles list
   - Result: CEO tokens were rejected with 403

2. BLANKET CEO REJECTION
   - checkStudentRegistrationStatus middleware rejected ALL CEO tokens
   - Applied globally to /api/tasks and /api/notifications routes
   - Result: CEO blocked even from read-only routes

3. NO CEO HANDLING IN QUERIES
   - Notification queries used user_id field
   - CEO has no database record (id="ceo" is virtual)
   - Result: Queries returned empty or failed
