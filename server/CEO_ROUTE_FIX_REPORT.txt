================================================================================
PROBLEM SUMMARY
================================================================================
The CEO login worked, but these GET routes returned 403 for CEO token:
- /api/missions
- /api/activities  
- /api/performance
- /api/audit-logs

Logs showed "[SECURITY] CEO token rejected on student/user route" for missions,
activities, and performance. audit-logs returned 403 with no [SECURITY] line.

================================================================================
ROOT CAUSE ANALYSIS
================================================================================
1. Routes used manual role checks that didn't include "ceo"
2. Routes blocked CEO with custom logic instead of using authorizeRoles()
3. audit-logs was restricted to "admin" only, excluding CEO
4. No pagination or filtering on audit-logs
5. CEO has no users record, so req.user.id-dependent code would fail

================================================================================
SECURITY PRINCIPLES ENFORCED
================================================================================

1. SHARED READ ROUTES: Use authorizeRoles("ceo", "manager", "admin")
   - CEO token accepted when JWT valid, role === "ceo", email === CEO_EMAIL
   - No database lookup for CEO (no req.user.id dependency)
   - Returns aggregate data for all students

2. STUDENT-ONLY ROUTES: Keep rejectCEO or checkStudentRegistrationStatus
   - Submitting work (POST /api/activities, POST /api/tasks/:id/submit)
   - Student profile edits (PUT /api/student/profile)
   - Student personal data (GET /api/activities/me, GET /api/tasks/my)

3. CEO-ONLY ROUTES: Use authorizeCEO middleware
   - Approve/reject registrations
   - Only accessible with valid CEO token

4. SEPARATION OF CONCERNS:
   - Students cannot read other students' data
   - Managers can only manage their assigned students
   - CEO and Admin have full visibility
   - Forged or unsigned tokens return 401

5. NO DATABASE DEPENDENCY FOR CEO:
   - CEO token has no id field (just role + email)
   - Handlers check req.user.role === "ceo" and return aggregate data
   - No User.findById(req.user.id) calls for CEO
